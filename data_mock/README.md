# Mock Data Directory

This directory contains **isolated demo data** for testing and demonstration purposes.

## Structure

```
data_mock/
├── raw/                    # Mock raw input files (SAP exports, uploads)
│   └── uploads/           # User-uploaded files in mock mode
└── curated/               # Mock processed/normalized data
    ├── line_items.parquet
    ├── events.parquet
    ├── event_items.parquet
    ├── client_profiles.parquet
    └── client_pattern_scores.parquet
```

## Purpose

**Mock mode** prevents contamination of real production data (`data/`) during:
- Feature development and testing
- UI demonstrations for external stakeholders
- Training sessions and tutorials
- Rapid iteration with reduced dataset size (5 clients vs 72)

## Activation

### Streamlit UI
1. Launch app: `streamlit run app/streamlit_app.py`
2. Sidebar → 📤 Dati → Enable "Usa Mock mode (isola i file)"
3. Verify red badge "🧪 DEMO DATA" appears at top

### CLI Pipeline
```powershell
$env:USE_MOCK="true"
python -m src.pipeline.run_all
```

## Dataset Characteristics

**Generated by**: `scripts/create_mock_data.py`

| Metric | Value |
|--------|-------|
| **Clients** | 5 (DEMO_C01 to DEMO_C05) |
| **Date range** | 2023-12-01 → 2024-03-03 (3 months) |
| **Events** | 5 (weekly cadence, 7-day gaps) |
| **Line items** | 10 invoices |
| **Currency** | EUR only |
| **Amounts** | 1,000 - 10,000 EUR |

**Pattern characteristics**:
- FIFO score: 0.6-0.9 (dominant policy)
- Same period score: 0.8-0.95
- Weekly periodicity: 0.6-0.9
- Stability index: 0.65-0.8

## Generation

Create/recreate mock dataset:
```powershell
python scripts\create_mock_data.py
```

This will generate 5 parquet files in `data_mock/curated/` with synthetic payment patterns.

## Safety Guarantees

✅ **Mock mode CANNOT**:
- Read from `data/` directory
- Write to `data/` directory
- Modify real production data

✅ **Real mode CANNOT**:
- Read from `data_mock/` directory
- Write to `data_mock/` directory
- Contaminate demo data

**Segregation verified by**: `scripts/test_mock_isolation.py`

## Client Naming Convention

- **Real clients**: `C001`, `C002`, `21000203`, etc. (variable format)
- **Mock clients**: `DEMO_C01`, `DEMO_C02`, ..., `DEMO_C05` (prefixed)

This naming convention makes it immediately obvious when viewing mock data.

## Usage Examples

### Example 1: Safe Testing
```powershell
# Test new feature with mock data
$env:USE_MOCK="true"
python -m src.features.make_features \
    --events data_mock/curated/events.parquet \
    --output data_mock/curated/train_features.parquet

# Real data remains untouched
ls data\curated\  # No train_features.parquet created
```

### Example 2: UI Demo
```powershell
# Launch in mock mode
streamlit run app\streamlit_app.py

# Enable toggle → Badge appears → Only DEMO_C* clients visible
# Share screen with stakeholders → No sensitive data exposed
```

## Maintenance

**Regenerate mock data** if:
- Schema changes in real data (new columns added)
- Need different client count or date range
- Testing specific edge cases (nulls, negatives, multi-currency)

Edit `scripts/create_mock_data.py` to customize generation parameters.
